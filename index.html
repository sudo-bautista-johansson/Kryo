1. Introduction

Kryo is a systems programming language where the type system knows more than the type. It statically tracks how much a value may hold, where it lives, and what state it is in, so whole classes of bugs are caught before the program runs: an index that walks off an array, a buffer pushed past its capacity, a file used after it was closed, a number that silently wraps around.

It runs on two engines from one front end: a reference interpreter (kryo run) that executes the whole language, and a native backend (kryo build) that lowers it to LLVM IR and produces a real executable. Both are checked by a differential test suite that requires them to print exactly the same output.

What makes Kryo different

IdeaWhat it means when you write code
Capacity is part of the typeBoundedVec<i32, 4> can never hold five elements, and Bounded<i32, 0, 100> can never leave its range. A literal outside the range is a compile error; a computed value is checked when it is produced. No allocator, no runtime library.
Memory domains are typesStack<T>, Heap<T>, GPU<T>, Shared<T>, Persistent<T>, Distributed<T> and Transfer<T> each carry a lifetime model. Moving data between them is an explicit operation, never an accident.
Resources are state machinesFile<Open> becomes File<Closed> when you close it. Reading a closed file, closing it twice, or forgetting to close it are all rejected by the checker, not discovered in production.
Contracts are part of the signaturerequires and ensures sit next to the parameters and run before and after the body, so a function documents and enforces its own rules.
Borrows end at their last useNon-lexical lifetimes: a reference freezes its owner only while it is still going to be used, so ordinary, readable code compiles without lifetime annotations.
Concurrency is a first-class valueThread::spawn, Atomic<i32>, async fn and .await are built in, with the type system tracking a thread handle until it is joined.
Diagnostics that teachEvery error carries a code, a source span, a label under the offending text, and usually a suggestion. kryo explain E0004 prints the long form.

Where Kryo fits

The one-minute version

If you know C or Rust, Kryo will feel familiar: braces, fn, let mut, struct, enum, match, traits and generics. What it adds is a type system that also counts capacity, location and state, and a set of runtime checks that make those promises real in both engines.

The root Cargo.toml declares a package without any targets, so a plain cargo build --release finishes successfully and produces no binary. Build with --workspace (or -p kryo-cli).

Environment and configuration

  • Kryo reads no environment variables of its own.
  • kryo build invokes D:\LLVM\bin\clang.exe (and lld-link.exe as a fallback). If that path does not exist, build reports a toolchain failure — run is unaffected.
  • Package metadata lives in Kryo.toml in the project directory (see Project layout).

3. Quick start tutorial

This walkthrough builds a small program that uses functions, a struct, a collection and a contract. Every step is executable as written.

Step 1 — a program that returns a value

fn main() -> i32 {
    let total: i32 = 40 + 2;
    println("total = {}", total);
    return total;
}
kryo run step1.kyo
total = 42

✓ Execution complete
Result: 42

main returns i32; the interpreter prints it after Result:.

Step 2 — a function

fn average(a: i32, b: i32) -> i32 {
    return (a + b) / 2;
}

fn main() -> i32 {
    println("average = {}", average(80, 90));
    return 0;
}

fn declares a function; parameters are name: Type; the arrow gives the return type. Calls are name(arg, …).

Step 3 — a struct with a method

struct Counter {
    value: i32,
}

impl Counter {
    fn new(start: i32) -> Counter {
        return Counter { value: start };
    }
    fn next(self) -> i32 {
        return self.value + 1;
    }
}

fn main() -> i32 {
    let c: Counter = Counter::new(41);
    println("next = {}", c.next());
    return 0;
}
Struct literals need every field

Counter { value: start } names the field explicitly — Kryo has no field shorthand and no default field values.

Step 4 — a collection

fn main() -> i32 {
    let mut scores = Vec::new();
    scores.push(70);
    scores.push(95);
    scores.push(88);
    println("count = {}", scores.len());
    return 0;
}

Step 5 — a contract

fn percent(part: i32, whole: i32) -> i32
    requires whole > 0
    ensures result >= 0
{
    return part * 100 / whole;
}

fn main() -> i32 {
    println("{}%", percent(3, 4));
    return 0;
}

Output: 75%. Calling percent(3, 0) fails at runtime with error[E0010], because requires whole > 0 is checked before the body runs.

Both clauses are enforced, and they guard different mistakes. requires rejects a call that was never valid; ensures rejects a body that broke its promise. If the guard passes and the body still returns something it should not, the function is stopped before the value reaches the caller:

fn ratio(value: i32) -> i32
    requires value >= 0
    ensures result >= 0
{
    // The guard accepts this call, but the body returns a negative number.
    return 0 - value;
}

fn main() -> i32 {
    return ratio(5);   // error[E0010]: the contract does not hold
}

The bad value never escapes the function, so every caller can rely on the signature without reading the body.

Step 6 — check, then run

kryo check main.kyo     # front end only: no execution, no artifacts
kryo run main.kyo       # compile-in-memory and execute
kryo explain E0010      # what the contract error means

4. Design principles

Six rules explain almost every decision in the language. Knowing them makes the rest of this reference predictable.

PrincipleConsequence you can rely on
Say what is true, not what is comfortableIf a program cannot be executed safely, it does not compile. There is no “undefined behaviour” category to fall into.
One front end, two engineskryo run and kryo build accept exactly the same programs and produce the same results.
Errors are a feature of the interfaceCapacity, states and contracts appear in the type and in the signature, so reading a function tells you what it will refuse.
Explicit is better than implicitNo implicit numeric conversion, no implicit ownership transfer between domains, no implicit suspension point.
Pay for what you useCapacity, domains and contracts cost nothing at run time unless a computed value has to be checked.
Teach while you failEvery rejection names the rule, the place, and the usual fix.

5. Syntax reference

Source files and comments

Kryo source files use the .kyo extension and are UTF-8. A byte-order mark is skipped.

// A line comment.

/* A block comment. */

fn main() -> i32 {
    return 0;   // trailing comment
}

/// is a documentation comment: kryo docs captures it and attaches it to the declaration that follows.

Identifiers

Identifiers start with a letter or _ and continue with letters, digits or _. Unicode letters are accepted.

fn main() -> i32 {
    let total: i32 = 1;
    let _unused: i32 = 2;
    let nombre: i32 = 3;
    return total + _unused + nombre - 5;
}

fn main() -> i32 {
    let tabbed: String = "a\tb";
    let quoted: String = "she said \"hi\"";
    println("{}|{}", tabbed, quoted);
    return 0;

Variables and mutability

fn main() -> i32 {
    let fixed: i32 = 10;        // immutable
    let mut counter: i32 = 0;   // reassignable
    counter = counter + fixed;  // only `mut` bindings accept assignment
    let shadowed: i32 = counter;
    let shadowed: i32 = shadowed + 1;   // a new binding, not an assignment
    return shadowed;
}

Type annotations are optional: let x = 1; infers i32.

Statements and blocks

  • A block { … } contains statements; its final expression is the block's value.
  • Statements end with ;. The final expression of a block may omit it.
  • let also accepts an omitted ;.
  • A bare { … } block is a statement and introduces a scope.

Conditionals

fn main() -> i32 {
    let n: i32 = 7;
    if n > 10 {
        println("large");
    } else {
        if n > 5 {
            println("medium");
        } else {
            println("small");
        }
    }
    return 0;
}
else if chains of any length

if … else if … else if … else nests to any depth. The formatter prints them as nested else { if … } blocks, which means the same thing.

Loops

fn main() -> i32 {
    let mut i: i32 = 0;
    let mut total: i32 = 0;
    while i < 5 {
        total = total + i;
        i = i + 1;
    }

    let values: [i32; 3] = [10, 20, 30];
    for v in values {
        total = total + v;
    }

    for n in range(0, 3) {
        total = total + n;
    }
    return total;   // 10 + 60 + 3 = 73
}
break and continue work

break leaves the innermost loop and continue starts the next iteration, in while and in for alike. Both engines agree: the interpreter implements them and kryo build emits the corresponding branches.

Functions

fn add(a: i32, b: i32) -> i32 {
    return a + b;
}

fn no_result(message: String) {
    println("{}", message);
}

fn main() -> i32 {
    no_result("side effect");
    return add(1, 2);
}

Structs, enums, impls, traits

struct Point {
    x: i32,
    y: i32,
}

enum Direction {
    North,
    South,
}

trait Magnitude {
    fn magnitude(self) -> i32;
}

impl Magnitude for Point {
    fn magnitude(self) -> i32 {
        return self.x + self.y;
    }
}

fn main() -> i32 {
    let p: Point = Point { x: 3, y: 4 };
    let d: Direction = Direction::North;
    match d {
        Direction::North => return p.magnitude(),
        Direction::South => return 0,
    }
}

Pattern matching

fn classify(n: i32) -> i32 {
    match n {
        0 => return 100,
        x => return x * 10,
    }
}

fn main() -> i32 {
    match Option::Some(5) {
        Option::Some(value) => println("got {}", value),
        Option::None => println("nothing"),
    }
    return classify(3);
}

Patterns: literals, identifiers (binding), _, tuples, enum variants with payloads, Option/Result, and optional guards (pattern if condition => …).

Unsafe blocks and FFI

extern "C" {
    fn puts(message: *const u8) -> i32;
}

fn main() -> i32 {
    unsafe {
        puts("called through the C ABI");
    }
    return 0;
}

Calling an extern "C" function outside unsafe is rejected with E0012. The interpreter does not perform foreign calls: it returns the zero value of the declared return type.

Attributes

#[repr(C)]
struct Packet {
    id: u32,
    size: u16,
}

fn main() -> i32 {
    return 0;
}

#[repr(C)] is parsed and recorded; the interpreter does not use it.

6. Operators and precedence

Precedence follows C, which keeps expressions predictable for systems programmers. Operator associativity is left-to-right except for assignment, which is parsed as a low-precedence binary operator.

LevelOperatorsAssociativityResult
1 (lowest)= += -= *= /= %= &= |= ^= <<= >>=leftassigned value
2||leftbool
3&&leftbool
4|leftinteger
5^leftinteger

12as (postfix cast), unary - ! ~ * & &mut—see below

fn main() -> i32 {
    // * binds tighter than +
    println("{}", 1 + 2 * 3);        // 7
    println("{}", (1 + 2) * 3);      // 9

    // left associativity
    println("{}", 10 - 3 - 2);       // 5
    println("{}", 100 / 10 / 5);     // 2

    // comparison binds tighter than &&
    if 1 < 2 && 2 < 3 {
        println("both");
    }

    // bitwise
    println("{} {} {}", 12 & 10, 12 | 10, 12 ^ 10);   // 8 14 6
    println("{} {} {}", 12 << 2, 12 >> 2, ~12);      // 48 3 -13
    return 0;
}

Arithmetic rules

  • Integers are 64-bit signed values internally; the declared type governs checking and display.
  • Integer / truncates toward zero. Division or remainder by zero is a checked runtime error (E0009) — not undefined behaviour.
  • Shift amounts must be in 0..64; anything else is a runtime error.
  • There is no implicit integer↔float conversion. Use as.
  • + also concatenates two String values.

Assignment

fn main() -> i32 {
    let mut x: i32 = 1;
    x = x + 41;          // plain assignment: supported
    let mut data: [i32; 2] = [1, 2];
    data[0] = 7;         // index assignment: supported
    return x + data[0];  // 49
}
Compound assignment works

+= -= *= /= %= &= |= ^= <<= >>= are all accepted; the parser lowers x op= y to x = x op y, so the type checker, the interpreter and the native backend all see the same form.

Kryo is statically typed. Annotations on bindings, parameters and return types are checked; a binding without an annotation takes the type of its initialiser.

Capacity-aware types

fn main() -> i32 {
    // The range is part of the type; a literal outside [0, 100] is a compile error.
    let percent: Bounded<i32, 0, 100> = 90;

    // The capacity is part of the type; pushing past it is an error.
    let mut buffer: BoundedVec<i32, 4> = BoundedVec::new(4);
    buffer = buffer.push(1);
    buffer = buffer.push(2);

    println("{} / {}", percent, buffer.capacity());
    return 0;
}

Resource types

A resource carries a state in its type: File<Open>, File<Closed>, Mutex<Locked>, Socket<Connected>.

fn main() -> i32 {
    let f = File::open("data.bin");   // File<Open>
    let d = File::read(f);            // i32; f is still Open
    let c = File::close(f);           // File<Closed>
    return d;
}

Reading c afterwards is E0011, and closing it twice is too.

Type inference and conversion

fn main() -> i32 {
    let inferred = 7;             // i32
    let f: f64 = inferred as f64; // explicit conversion
    let back: i32 = f as i32;     // truncates toward zero
    let flag: bool = true;
    let n: i32 = flag as i32;     // 1
    return back + n;
}

as converts between numeric types and between bool and integers. There is no implicit conversion: mixing i32 and f64 in arithmetic is an error, not a silent promotion.

8. Memory and safety

Kryo's safety story is deliberately narrow: it gives you explicit domains, checked indices, checked arithmetic failure modes, resource states, and a move checker. It does not attempt Rust's lifetime analysis.

Where a value lives is in its type

fn main() -> i32 {
    let value: i32 = 10;

    let on_stack = Stack::alloc(value);   // transparent: on_stack is an i32
    let on_heap = Heap::alloc(value);     // a handle
    on_heap.write(on_stack + 1);

    println("stack {}, heap {}", on_stack, on_heap.get());
    return 0;
}

Persistence

fn main() -> i32 {

    counter.write(counter.get() + 1);
    println("counter = {}", counter.get());   // 42, and "42" is on disk

}

9. Functions and generics

Declaration and calls

fn add(a: i32, b: i32) -> i32 {
    return a + b;
}

fn greet(name: String) {
    println("hello, {}", name);
}

fn main() -> i32 {
    greet("world");
    return add(2, 3);
}

Arguments are positional and count-checked: passing one argument to a two-parameter function is E0003 with the expected arity in the message. There are no default arguments and no overloading.

Recursion

fn fib(n: i32) -> i32 {
    if n < 2 {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

fn main() -> i32 {
    return fib(10);   // 55
}

The interpreter runs on a dedicated 256 MiB stack, so recursion up to roughly ten thousand nested calls works before the host stack is exhausted. Treat that as an implementation limit, not a language guarantee.

Generics

fn identity<T>(value: T) -> T {
    return value;
}

struct Container<T> {
    value: T,
}

// A parameterised `impl Container` is handled by the language rules; a plain
// `impl Container` covers every instantiation.
impl Container {
    fn get(self) -> i32 {
        return self.value;
    }
}

fn main() -> i32 {
    let n: i32 = identity(42);
    let c: Container<i32> = Container { value: 7 };
    return n + c.get();
}

Associated functions and methods live in impl Container { … }. A parameterised header (impl<T> Container<T>) is accepted and covers every instantiation.

Generic parameters can carry trait bounds (fn f<T: Describable>(x: T)); bound violations are reported as E0003. Monomorphisation is performed during type checking.

Traits

trait Describable {
    fn describe(self) -> i32;
}

struct Sensor {
    reading: i32,
}

impl Describable for Sensor {
    fn describe(self) -> i32 {
        return self.reading;
    }
}

fn main() -> i32 {
    let s: Sensor = Sensor { reading: 42 };
    return s.describe();
}

Traits can also be implemented for primitive types, in which case the method is available on values of that type (impl Doubler for i32 { fn doubled(self) -> i32 { … } }). Trait objects work: a &dyn Trait parameter accepts a reference to any implementing type and dispatches on the runtime type.

Contracts

fn clamp_value(value: i32, low: i32, high: i32) -> i32
    requires low <= high
    ensures result >= low
    ensures result <= high
{
    if value < low {
        return low;
    }
    if value > high {
        return high;
    }
    return value;
}

fn main() -> i32 {
    return clamp_value(15, 0, 10);   // 10
}
ClauseCheckedError
requires conditionOn function entryE0010
ensures conditionOn return; result is bound to the valueE0010

Async functions

async fn compute() -> i32 {
    return 41;
}

fn main() -> i32 {
    let value = compute().await;
    return value + 1;
}

An async fn returns a future; .await resolves it immediately in the interpreter. async { … } blocks are also supported. There is no scheduler and no concurrency: the future is eager.

10. Data structures

Arrays

fn main() -> i32 {
    let mut data: [i32; 4] = [10, 20, 30, 40];
    data[1] = 21;
    let filled: [i32; 3] = [7; 3];   // [7, 7, 7]
    return data[0] + data[1] + filled[0];
}

Fixed size is part of the type. Constant out-of-range indices are rejected by the type checker.

Tuples

fn main() -> i32 {
    let pair = (40, 2);
    match pair {
        (a, b) => return a + b,
    }
}

Tuples are constructed, destructured, indexed with t.0 / t.1, and compared with ==.

Vectors

fn main() -> i32 {
    let mut v = Vec::new();
    v.push(1);
    v.push(2);
    println("len = {}", v.len());
    for value in v {
        println("{}", value);
    }
    return 0;
}

Bounded vectors

fn main() -> i32 {
    let mut buffer: BoundedVec<i32, 4> = BoundedVec::new(4);
    buffer = buffer.push(1);
    buffer = buffer.push(2);
    buffer = buffer.push(3);
    println("{}/{}", buffer.len(), buffer.capacity());
    return 0;
}

Maps

fn main() -> i32 {
    let m = HashMap::new();
    m.insert("a", 1);
    m.insert("b", 2);
    m.insert("a", 3);            // overwrites
    println("size = {}", m.len());        // 2
    println("has a: {}", m.contains_key("a"));
    match m.get("b") {
        Option::Some(v) => return v,
        Option::None => return 0,
    }
}

Keys and values are values of any type the interpreter can compare; get returns an Option. remove(key) returns the map without that key.

Structs

struct Config {
    retries: i32,
    verbose: bool,
}

fn main() -> i32 {
    let mut c: Config = Config { retries: 3, verbose: true };
    c.retries = c.retries + 1;
    if c.verbose {
        println("retries = {}", c.retries);
    }
    return 0;
}

Field access and whole-field assignment are supported. A struct value is copied on assignment; there are no constructors beyond associated functions in impl.

Enums and pattern matching

enum Status {
    Idle,
    Running,
    Failed,
}

fn label(s: Status) -> i32 {
    match s {
        Status::Idle => return 0,
        Status::Running => return 1,
        Status::Failed => return 2,
    }
}

fn main() -> i32 {
    return label(Status::Running);
}

Variants may carry a payload (Circle(i32)) and be destructured in match. A payload received through a parameter can be matched and used directly; the binding gets the payload type.

mod name { … } declares a module inline. mod name; loads name.kyo from the directory of the file that declares it, recursively, so a program can be split across files. A non-pub function inside a module is not reachable through a qualified path from outside — calling it is E0004.

13. Command line

One binary, kryo. Every subcommand shares the global flags --color auto|always|never and --message-format human|short|json.

18. Internals

Two back ends share one front end.

source
  -> lexer.rs        tokens (terminated by an explicit EOF)
  -> parser.rs       AST
  -> semantic.rs     name resolution, scopes, suggestions
  -> types.rs        inference, capacity, contracts, trait dispatch
  -> ownership.rs    moves, borrows, resource states, leaks
  -> optimize.rs     constant propagation, dead code elimination
  -> interpreter.rs  reference semantics   (kryo run)
  -> llvm_codegen.rs textual LLVM IR -> clang -> executable   (kryo build)

The interpreter runs on a dedicated 256 MiB thread, so recursion depth is bounded by memory rather than by the host stack. The native backend lowers arithmetic, formatting, calls, recursion, loops, arrays, const/static and traits-free structs; anything it cannot represent raises E0006 instead of emitting wrong code.

19. Safety rules

What the compiler guarantees while you code, and which diagnostic you get when a rule is invalid. These are rules of the language, not suggestions: there is no flag that turns them off.

A capacity is never exceededOn every push and every bounded bindingE0009 / E0003

The unsafe boundary

unsafe { … } is the only place where the compiler stops checking: raw pointer arithmetic and foreign calls live there. Everything else in the language is checked, which is why an unsafe block is worth a comment explaining the invariant it relies on.

fn main() -> i32 {
    // Safe: no pointer arithmetic, no foreign call.
    let data: [i32; 4] = [1, 2, 3, 4];
    let mut sum: i32 = 0;
    for v in data { sum = sum + v; }
    sum
}

Where Kryo is genuinely strong

  • Capacity as a type. BoundedVec<T, N> and Bounded<i32, lo, hi> are checked at compile time and at runtime — no silent overrun.
  • Resource state machines. Use-after-close, double-close and an unclosed file are all reported before the program runs.
  • Contracts. requires/ensures are executed, so a violated precondition names the function and the span.
  • Diagnostics. Every failure carries a code, a span, a label and usually a suggestion — the same shape as rustc's.
  • Memory domains. Stack, Heap, GPU, Shared, Persistent, Distributed and Transfer are first-class in the type system.

21. FAQ and troubleshooting

Why does cargo build --release produce no binary?

The root package has no targets. Use cargo build --release --workspace.

Why do my computed values disappear from the kryo build output?

They do not any more: formatting, arithmetic, calls, recursion, loops, arrays and const are all compiled. Constructs the backend cannot lower (for example printing a struct) fail with E0006 instead of printing {}.

Why does kryo check reject a program that kryo run executes?

It no longer does. check runs the same front end as run (lexer, parser, resolver, type checker, borrow checker) and then generates IR without linking.

My while loop never ends even though it has a break

It should end: break leaves the innermost loop and continue skips to the next iteration, in both while and for. If a loop still runs forever, check that the condition variable is updated on every path.

Why is x += 1 rejected?

It is not: all ten compound assignments work and are lowered to x = x + 1. If you see an error here, make sure x is declared with let mut.

Why does if s.contains("x") fail to compile?

It compiles. contains is typed bool, like is_some, is_empty and the other predicates.

How do I print a value of an unknown type?

println("{}", value) renders integers, floats, booleans, strings, structs, enums, arrays, tuples, optionals and domain handles. Use .to_string() when you need the text as a String.

Why did the caret point at the wrong thing?

It should not. Columns count characters (not bytes), tabs are expanded, and a BOM is skipped. If a caret is misaligned, that is a bug — please report the file with the diagnostic.

How do I get machine-readable errors?

kryo run file.kyo --message-format json. Each diagnostic is one JSON object on stderr with severity, code, category, message, spans and suggestions.

How do I disable colours in CI?

Nothing to do: colour is off when stderr is not a terminal. To be explicit, pass --color never.

Where is the standard library?

There is no separate library crate. The built-ins listed in Built-in library are provided by the interpreter; std/ in the repository is an empty placeholder.

Can I call C functions?

You can declare them with extern "C" and call them inside unsafe. The interpreter does not perform the foreign call — it returns the zero value of the declared type — so real FFI requires the native back end, which is incomplete.

Why does kryo explain E9999 fail?

Only codes the compiler can actually emit have explanations. Run kryo explain without an argument to list them.

How deep can recursion go?

About ten thousand nested calls before the host stack is exhausted; the interpreter runs on a 256 MiB thread. Deeper recursion aborts the process rather than raising a diagnostic.

Something crashed with E0008. What now?

E0008 means an internal invariant broke — the program is not at fault. Report it with the source and the command. The exit status is 3 so scripts can tell it apart from a normal compile error.
